# Eugene Work

**Eugene Work** — единый рабочий кабинет экосистемы Eugene / Symbiont: документы, заметки, таблицы, презентации, календарь и файлы в одном интерфейсе.

> Статус: **MVP-прототип интерфейса**. Текущая версия работает локально в браузере через `localStorage`. Это не развернутый облачный сервис: аккаунты, серверное хранилище, совместное редактирование и межустройственная синхронизация пока не подключены.

## Цели

- Единое рабочее пространство вместо набора несвязанных приложений.
- Общая навигация, поиск, создание материалов и единая модель метаданных.
- Быстрый интерфейс без тяжёлого клиентского стека на первом этапе.
- Локальное сохранение как автономный режим и основа для последующей синхронизации.
- Заменяемые адаптеры редакторов и хранилища, чтобы не писать офисные движки с нуля.

## MVP

Откройте `index.html` в браузере или включите GitHub Pages для репозитория.

- **Обзор** — недавние материалы и быстрые действия.
- **Календарь** — создание и просмотр событий.
- **Заметки** — быстрые текстовые записи.
- **Документы** — базовый текстовый редактор.
- **Таблицы** — редактируемая сетка ячеек, импорт/экспорт CSV.
- **Презентации** — создание слайдов, редактирование заголовка и содержания, режим показа.
- **Файлы** — список созданных объектов и экспорт резервной копии JSON.
- **Поиск** — поиск по локальным материалам.

## Архитектурный принцип

`Eugene Work UI → Workspace Domain → Sync/Storage Adapters → Server & Connectors`

- UI не должен владеть правилами доступа и синхронизации.
- Все объекты имеют стабильный ID, тип, время создания/обновления и владельца в будущем.
- Локальная запись — отдельная операция от серверного подтверждения.
- Для синхронизации потребуются версия объекта, журнал изменений, идемпотентные операции и разрешение конфликтов.
- Секреты и токены нельзя хранить в клиентском коде или репозитории.
- Не обещаем end-to-end encryption, real-time collaboration или облачную синхронизацию до их фактической реализации и тестирования.

## Синтез существующих решений

Не изобретать заново зрелые редакторные движки. После проверки актуальных лицензий и возможностей рекомендуется оценить:

- **Tiptap / ProseMirror** — текстовые документы и расширяемая модель содержимого.
- **Univer** — табличный движок; отдельно проверить нужные функции и лицензионные ограничения.
- **ONLYOFFICE Docs** или **Collabora Online** — альтернативы для встраивания полноценных офисных редакторов, особенно если нужен импорт/экспорт форматов Office.
- **FullCalendar** — календарный интерфейс; серверная модель событий остаётся нашей.
- **Yjs** — возможный CRDT-слой для совместного редактирования, только после проектирования хранения, авторизации и восстановления.

Это варианты для технической оценки, а не утверждение, что они уже подключены. Необходимо отдельно проверить текущие лицензии, self-hosting, мобильную поддержку, экспорт, доступность функций в бесплатной редакции и стоимость эксплуатации.

## План развития

1. **MVP UI**: навигация, CRUD, поиск, локальное сохранение, экспорт/импорт.
2. **Надёжность данных**: IndexedDB, миграции схемы, автосохранение, восстановление и тесты.
3. **Backend**: аутентификация, API, база данных, объектное хранилище, права доступа.
4. **Синхронизация**: outbox, версии, повтор запросов, конфликты и офлайн-очередь.
5. **Интеграции редакторов**: подключение выбранных движков по лицензии и требованиям.
6. **Совместная работа**: присутствие, комментарии, история, CRDT/OT и аудит доступа.
7. **Продукционный запуск**: резервные копии, мониторинг, миграции, безопасность и нагрузочные тесты.

## Важно

GitHub Pages может размещать только статическую клиентскую часть. Он не предоставляет Eugene Work полноценный backend, защищённую пользовательскую базу, фоновые задачи или гарантированную синхронизацию между устройствами. Для облачного продукта нужен отдельный серверный слой.
